# Proofly UI/UE 视觉升级设计方案

**Date:** 2026-05-15  
**Product:** 凭保 Proofly  
**Scope:** dev0 原型视觉与交互质感升级  
**Source:** `proofy_ui_ux_redesign_upgrade_spec_zh.md`、当前项目实际 UI/UE、既有产品需求文档  

## 1. 目标

本次升级不是重做产品，也不是改变信息架构，而是在保留当前轻量、清晰、可用的基础上，把 Proofly 从“实用工具原型”升级为更高级、更现代、更有品牌记忆点的 iOS 精品 App 原型。

升级后的产品气质应接近：

- 50% Apple 原生秩序感
- 30% Linear / Arc / Raycast 式高级效率工具质感
- 20% AI Future 的空间光感与智能提示感

核心目标：

- 增强高级感、空间层次和品牌识别。
- 强化首页第一眼的视觉冲击。
- 让卡片、TabBar、Sheet、Toast、Paywall 等组件形成统一系统。
- 提升动效、按压反馈和页面进入节奏。
- 不破坏资料管理类 App 的长期扫描效率。

## 2. 产品边界

当前 V1 仍然遵守既有产品边界：

- 不做登录、账号、云同步。
- 不做 OCR、AI 自动识别、AI 字段提取。
- 不做法律、税务、保险、医疗结论建议。
- 不把产品做成 CRM、记账、合同 SaaS 或文件网盘。

升级文档中提到的 AI 感，只作为视觉与文案层面的“智能提示 / 本地状态洞察”表达，不承诺真实 AI 能力。

允许出现：

- “本地状态”
- “整理建议”
- “即将到期”
- “缺少标题或关联对象”
- “本地安全状态”

避免出现：

- “AI 已识别”
- “AI 分析风险”
- “自动提取字段”
- “智能识别合同”
- “问我任何资料问题”

## 3. 升级策略

推荐采用分阶段升级，先改最能提升整体气质的视觉系统和首页，再逐步扩展到列表、详情、设置和 Pro 页面。

### 第一阶段：视觉系统与首页

第一阶段目标是让产品“立刻高级 70%”，但尽量少动业务逻辑。

范围：

- 全局颜色系统
- 背景空间光感
- 卡片系统
- 首页 Hero
- Floating TabBar
- 基础微交互

不在第一阶段做：

- 暗黑模式完整适配
- 真实 AI Orb
- 搜索能力改造
- 详情页大结构重写
- 复杂粒子或 MeshGradient 动画

### 第二阶段：核心页面体验

范围：

- 记录列表视觉升级
- 记录详情顶部资产卡和时间线表达
- 对象详情时间线强化
- Pro 升级页高级化
- 设置页和模板页视觉统一

### 第三阶段：增强能力与深色模式

范围：

- 暗黑模式
- 更完整页面转场
- 智能提示模块增强
- 轻量动态光效
- 视觉记忆点进一步强化

## 4. 全局视觉系统

### 4.1 颜色

保留既有品牌方向，但把普通蓝色升级为更高级的蓝紫光感。

建议 tokens：

- `primary`: `#4C6FFF`
- `primaryStart`: `#5B7CFF`
- `primaryEnd`: `#7B61FF`
- `mint`: `#31C48D`
- `warning`: `#FFB648`
- `danger`: `#FF5A6B`
- `background`: `#F5F7FB`
- `surface`: `rgba(255,255,255,0.72)`
- `textPrimary`: `#101828`
- `textSecondary`: `#667085`
- `textTertiary`: `#98A2B3`

现有 `#2563FF` 可以继续用于链接、选中态和系统动作，但 Hero、TabBar、Pro 页等品牌核心区域应使用蓝紫渐变。

### 4.2 背景

当前纯色背景偏平。升级后使用“冷雾底色 + 环境光”：

- 基础背景为 `#F5F7FB`。
- 页面背景叠加 2-3 个极淡 radial glow。
- 光斑颜色以蓝、紫、薄荷绿为主，透明度低。
- 不使用明显漂浮装饰球，不做霓虹或 Web3 感。

Web 原型中可通过伪元素或页面背景层实现，不需要真实粒子系统。

### 4.3 卡片系统

建立统一卡片层级，替换分散的白色圆角容器。

卡片类型：

- `HeroCard`: 首页主视觉和 Pro Hero。
- `GlassCard`: 常规分组容器。
- `FloatingCard`: 首页对象、提醒、记录模块。
- `MiniMetricCard`: 数字摘要、状态 pill。
- `ActionCard`: 添加、导出、备份等动作入口。

基础样式：

- 半透明白色背景。
- 20-24px 圆角用于 Hero / 大卡片，14-16px 用于列表组。
- 极轻边框高光。
- 低透明柔和阴影。
- 按压时轻微缩放到 `0.97-0.985`。

注意：不要卡片套卡片。列表页仍要保持可扫描密度，不应全部改成巨型卡片。

## 5. 首页升级

首页是第一阶段重点。

### 5.1 新结构

首页保持当前功能内容，但重排为更有节奏的 dashboard：

1. 顶部搜索框
2. Dynamic Hero Area
3. 智能提示 / 本地状态卡
4. 常用对象横向卡片
5. 即将到期
6. 最近记录

### 5.2 Dynamic Hero Area

Hero 不再只是统计卡，而是“数字资料保险箱状态卡”。

内容：

- 当前资料箱名称：如“家庭资料箱”
- 主数字：`46`
- 说明：`份重要资料`
- 本地安全状态：`已保存在这台 iPhone`
- 状态 pill：`4 待整理`、`12 本月新增`、`5 近期提醒`

视觉：

- 蓝紫渐变背景。
- 柔和光感高光。
- 半透明状态 pill。
- 大数字使用更强字重。
- 右上角保留资料箱切换和更多操作。

### 5.3 智能提示卡

新增一个不承诺 AI 的轻提示模块，文案使用“整理建议”或“本地提示”。

示例：

- `MacBook 保修还有 119 天`
- `4 条资料可以稍后整理`
- `建议本周导出一次本地备份`

视觉：

- 小型 GlassCard。
- 左侧使用发光图标或微型 orb 视觉。
- 右侧为一句主文案和一个轻操作。

禁止写成“AI 风险分析”或“AI 已识别”。

## 6. Floating TabBar

当前底部导航结构保留：首页、记录、中间添加、提醒、设置。

升级方向：

- TabBar 从贴底系统栏升级为轻浮空玻璃底栏。
- 背景使用半透明白 + blur。
- 底部保留安全区。
- 中间 `添加` 按钮继续作为视觉记忆点。
- 添加按钮可从普通渐变圆形升级为轻 Orb 质感，但文案仍是添加动作，不改成 AI 功能。

点击 `添加` 后继续展开：

- 添加记录
- 添加对象

展开层增加更柔和的 scale / fade 动画，遮罩不宜过黑。

## 7. 记录列表升级

记录列表不能牺牲效率。当前 grouped list 方向保留，但视觉升级为“Smart Document Row”。

升级点：

- 文件类型图标容器使用轻渐变底座。
- 重要状态用小角标表达，如“有提醒”“待整理”。
- 标题、金额、日期、对象关系层级更清晰。
- 分组容器使用 GlassCard，但 row 本身保持紧凑。
- 筛选 sheet 保持当前两栏结构，升级背景、选中态和底部按钮。

不建议：

- 把所有记录改成大型卡片瀑布流。
- 使用“AI 已识别”“可报销”等未实现标签。

## 8. 详情页升级

第二阶段重做详情页。

方向：

- 顶部增加资产卡 / 文件预览区域，类似 Apple Wallet 卡片展开。
- 关键字段不再像表格，而是分成“资料摘要”“附件”“提醒”“关联对象”“时间线”几个区块。
- 对象相关资料可以用 timeline 表达生命周期。

记录详情建议结构：

1. 顶部文件资产卡
2. 标题、类型、标签
3. 资料摘要
4. 附件列表
5. 提醒
6. 关联对象
7. 操作菜单

对象详情建议强化：

- 把当前事件时间线作为核心模块。
- 记录、附件、提醒指标保留。
- 导出资料包按钮使用更高级的 ActionCard。

## 9. Pro 页升级

Pro 页是变现重点，建议第二阶段处理。

升级方向：

- 顶部 Pricing Hero：`¥18 / 年` 更大、更有视觉中心。
- 标语从功能列表转为价值表达：`守护你的本地重要资料`
- 权益改成 2 列或纵向 Feature Card。
- 保留“继续使用免费版”“恢复购买”。
- 明确“不上传资料”“无广告”“到期不删除已有资料”。

不能写：

- 云同步
- 永久不限
- 法律效力

## 10. 动效原则

动效目标是“高级、克制、有惯性”，不是炫技。

基础规则：

- 按压反馈：scale `0.97-0.985`。
- Sheet：从底部 slide + fade，200-300ms。
- 卡片出现：fade + translateY + blur，错峰 30-50ms。
- TabBar 添加菜单：scale + opacity。
- Toast：从上或下轻滑入，自动消失。

避免：

- 夸张 bounce。
- 粒子持续大面积运动。
- 动效阻塞点击。
- 文字或布局跳动。

## 11. 技术落地建议

当前项目是 Next.js / React / Tailwind 原型，应先抽局部组件，而不是在每个页面继续写 raw style。

建议新增或重构：

- `components/proofly/visual-tokens.ts`
- `components/proofly/premium-card.tsx`
- `components/proofly/ambient-background.tsx`
- `components/proofly/metric-pill.tsx`
- `components/proofly/floating-tab-bar.tsx`
- `components/proofly/smart-insight-card.tsx`

第一阶段主要修改：

- `app/globals.css`
- `components/proofly/iphone-shell.tsx`
- `components/proofly/tab-bar.tsx`
- `components/proofly/screens/home.tsx`
- 少量共享样式组件

## 12. 验收标准

第一阶段完成后应满足：

- 第一眼不再像普通 iOS 设置 / 文件管理工具。
- 首页有明确品牌记忆点。
- 仍能快速理解：添加记录、查找资料、设置提醒、导出资料包。
- 视觉更高级，但没有牺牲列表扫描效率。
- 没有出现 OCR、AI 自动识别、AI 风险分析等越界能力。
- TabBar、卡片、Sheet、Toast 风格统一。
- 移动端 390x844 画布内没有文本溢出或操作遮挡。
- 动画轻柔，不拖慢操作。

## 13. 推荐实施顺序

1. 抽视觉 tokens、背景和卡片组件。
2. 升级首页 Hero、状态 pill、智能提示卡。
3. 升级 Floating TabBar 和添加菜单。
4. 统一 Sheet、Toast、按钮按压反馈。
5. 局部升级记录列表的 row 样式。
6. 截图检查 390x844 Showcase 和交互模式。
7. 再进入详情页、Pro 页和暗黑模式的第二阶段。
