# 凭保 Proofly dev0 UI/UE 生成文档

**Date:** 2026-05-11  
**Product Name:** 凭保  
**English Name:** Proofly  
**Purpose:** 记录当前 dev0 / v0 生成后的高保真 UI 原型实际效果，并作为后续继续调整 Proofly 原型的 UI/UE 基准。  
**Target Output:** 当前项目使用 Next.js / React / Tailwind 作为预览载体，模拟只面向 iOS App Store 上架的 iPhone App。视觉贴近 iOS 18 / SwiftUI 原生语言，同时呈现更简洁、更现代、更 premium 的海外 productivity / utility App 气质。预览环境包含“全部页面 Showcase”和“交互模式”两种入口，但 App 内界面仍应按 iPhone 原生结构理解，不能当作 Web App、H5、小程序或 Android 设计。  

## 1. 主提示词

请为一个只面向 iOS App Store 上架、使用 SwiftUI 实现的 iPhone App 生成高保真 UI 原型，应用名为“凭保 Proofly”。这是一个本地优先的重要资料富媒体备忘录，面向个人、家庭、老幼照护者、自由职业者、小微经营者和上班族。用户可以像写备忘录一样先保存一条记录：文字、照片、合同、票据、证照、保修卡、体检报告、检查单、处方、疫苗记录、付款截图、PDF 和普通文件都能放进去，再按资料箱、相关人或物、事件和提醒整理，需要时打包导出。

请生成一个贴近 iOS 18 / SwiftUI 原生风格、但明显更现代、更简洁、更酷、更适合海外 iOS 用户审美的 iPhone App 原型。不要生成 Android / Material Design 风格，不要做营销落地页，不要做说明型官网。第一屏就是 App 的可用界面。整体风格应像一个 premium personal utility App：冷静、可信、轻未来感、精致但不浮夸。视觉上以 Apple 原生 App、iOS 设置、文件、提醒事项、备忘录为基础，但加入定制品牌主题色、轻玻璃感、细腻浅色渐变、紧凑信息层级和流畅动效。

设计目标：

- 平台必须是 iOS SwiftUI App，画布以 iPhone 15 / 390x844 为主。
- 只考虑 iOS 手机端上架，不考虑 Android、Web App、H5、小程序、桌面端或响应式后台。
- 视觉必须像 SwiftUI 原生界面，而不是安卓 App、Material Design、桌面后台或营销网页。
- 交互必须简洁，减少一级入口和复杂管理感。当前原型底部导航实际呈现为 5 个视觉项：`首页`、`记录`、中间突出 `添加`、`提醒`、`设置`。其中 `添加` 不是内容页 Tab，而是底部中间的快捷操作入口，点击后在 Tab Bar 上方展开 `添加记录` 和 `添加对象` 两个动作。
- 使用 iOS 原生导航结构：`NavigationStack` 大标题、`TabView` 底部标签栏、`List` / `Form` / `Section`、`sheet`、`confirmationDialog`、`segmented Picker`、`Toggle`、`DatePicker`、iOS 原生搜索栏。
- 使用 iOS 原生排版：San Francisco / SF Pro 字体气质，large title、title2、headline、body、caption 的层级清晰。
- 使用 iOS 原生间距和圆角：页面边距 16pt，列表 row 高度接近系统默认，premium 卡片圆角 14-16pt，工具按钮使用 iOS 风格圆角矩形或圆形图标按钮。
- App 内业务图标首选 emoji，例如资料箱、空间、模板、资料类型、家庭成员、健康档案、项目、证书等都优先使用 emoji。底部 Tab、导航栏和系统动作按钮可以使用 SF Symbols 风格图标。不要使用 Material Icons。
- 所有字段都可选，用户可以只写一句话、只拍照或只导入文件后直接保存。
- 首版不做 OCR，不要出现“自动识别”“AI 提取”“扫描识别”等入口。
- 产品本地优先：不登录、不上传、不默认云同步、不接广告。
- 免费版和 Pro 年付版并存：免费版限制 1 个空间、30 条记录、3 个提醒，只能预览资料包；Pro 支持无限空间、无限记录、PDF / ZIP 导出、加密备份、备份恢复、自定义空间和自定义模板。
- 文案使用简体中文，少量英文只用于品牌名 Proofly 或技术格式 PDF / ZIP。
- 界面文案要口语化、短句化、容易理解，避免深奥产品概念和长段解释。尽量使用“保存资料”“稍后再补”“打包导出”“待整理”“到期提醒”这类用户一眼能懂的表达。

iOS 原生风格硬性要求：

- 必须使用 iOS 底部 Tab Bar，不要使用 Android Bottom Navigation 的 Material 样式。
- 必须使用 iOS 大标题导航，不要使用 Android 顶部 App Bar。
- 必须使用 iOS 原生列表分组样式，不要使用 Material Card 堆叠列表作为主结构。
- 必须使用 iOS Modal Sheet / Action Sheet 风格，不要使用 Android Dialog / Bottom Sheet 样式。
- 必须使用 iOS 原生 Toggle / Segmented Control / Date Picker 风格，不要使用 Material Switch、Material Chips 或安卓日期选择器。
- 不要使用右下角 Floating Action Button。当前原型采用底部 Tab Bar 中间的圆形 `添加` 控件，点击后展开两个横向快捷动作：`添加记录`、`添加对象`。
- 不要使用汉堡菜单、侧边抽屉、顶部返回箭头加居中标题的安卓导航模式。
- 不要使用 Roboto 字体、Material Icons、高海拔投影、彩色状态栏、安卓式圆角大卡片。
- 不要生成 Web Dashboard、Web App、H5 活动页、小程序或 Android 适配稿。

当前原型包含以下核心页面，并通过按钮、底部导航或 sheet 操作跳转：

1. 空间选择页
2. 空间首页
3. 快速添加记录页
4. 添加对象页
5. 记录 / 资料列表页
6. 记录详情页
7. 对象详情页，从首页常用对象、搜索结果、记录详情或添加对象保存后进入，不作为底部 Tab
8. 搜索页
9. 提醒页
10. 导出资料包页
11. 待整理记录页
12. 模板管理页
13. 新建 / 编辑模板页
14. 设置页
15. Pro 升级页或订阅弹窗
16. 权限拒绝 / 空状态 / 导入失败 / 保存失败等关键状态

视觉方向：

- 目标气质：premium iOS utility、海外 productivity App、轻未来感、冷静可信、交互克制。不是传统系统设置页，也不是营销风 App。
- 主体必须是浅色模式，但可以使用定制品牌主题色和细腻光感，形成更强辨识度。
- 品牌主色：Electric Blue `#2563FF`，用于主要按钮、Tab 选中态、链接、关键进度、活跃状态。
- 品牌辅助色：Mint Teal `#14C8A8`，用于成功、已保存、本地安全、备份完成等正向状态。
- 品牌强调色：Soft Indigo `#7C5CFF`，用于 Pro、模板、自定义、空间切换等高级能力。
- 背景色：Cool Mist `#F6F8FF`，比系统灰更清爽；分组背景和表单仍应接近 iOS 原生白色。
- 文字：主文字 `#101828`，次级文字 `#667085`，弱提示 `#98A2B3`。
- 危险色沿用 iOS Red `#FF3B30`；提醒色使用 iOS Orange `#FF9500` 或更轻的 amber tint。
- 首页、空间卡片、Pro 弹窗和状态摘要可以使用小面积品牌渐变，例如 Electric Blue 到 Soft Indigo，或 Electric Blue 到 Mint Teal；渐变必须轻、干净、局部使用，不要整屏深色铺满。
- 可使用轻玻璃感卡片：半透明白色、极轻边框、轻微 blur 感、柔和阴影，但不能做成厚重毛玻璃、霓虹赛博或游戏 UI。
- 列表页和表单页保持 iOS 原生 grouped list 的可读性；酷炫感主要体现在首页、关键状态、按钮、图标底色和动效，不牺牲长期使用效率。
- 不要使用漂浮装饰球、复杂插画背景、强烈霓虹、高饱和大面积紫色、深色 dashboard 或 Web3 风格。

界面应该像一个真正能用的 App，而不是产品介绍页。请使用真实样例数据展示资料、对象、提醒和导出内容。

如果生成工具无法直接生成 SwiftUI，请只把 HTML / React 当作预览载体，视觉和交互仍必须模拟 SwiftUI：iOS 状态栏、安全区、圆角屏幕容器、原生 Tab Bar、分组列表、原生表单、原生 sheet、emoji 业务图标和 SF Symbols 系统动作图标。不要把结果设计成 Web App。

## 2. 产品核心心智

凭保 Proofly 的核心不是“整理所有东西”，也不是替代 Apple 备忘录，而是“重要资料别再到处找”。它要像备忘录一样轻，但只服务合同、票据、证照、健康资料、经营资料、职业记录等重要内容。

核心路径：

写一句话 / 拍下或导入资料 → 先存起来 → 关联到人、物品或项目 → 设置到期提醒 → 需要时打包导出。

设计时应降低录入压力。新增记录时，页面要允许用户直接保存，不要强迫用户填完表单。未填写字段的记录可进入“待整理”列表，后续再补充标题、标签、对象或提醒。

### 2.1 文案语气

界面文案要像日常 App，而不是企业系统。少用抽象词，多用动作词。短句优先，尽量一屏能扫懂。

推荐表达：

- “先存起来”
- “稍后再补”
- “待整理”
- “添加提醒”
- “打包导出”
- “保存到本机”
- “最近添加”
- “即将到期”
- “找资料”
- “开通 Pro”

避免表达：

- “证据资产管理”
- “多维资料聚合”
- “对象关系建模”
- “结构化凭证体系”
- “业务闭环”
- “高级资料治理”

涉及产品内部概念时，可以这样转译：

| 内部概念 | UI 推荐文案 |
|----------|-------------|
| 空间 | 资料箱 / 家庭资料箱 / 经营资料箱 |
| 记录卡 / 资料 | 记录 / 资料 / 文件 |
| 对象 | 关联到 / 相关人或物 |
| 证据包 | 资料包 / 打包导出 |
| 未整理记录 | 待整理 |
| 模板 | 模板 / 常用字段 |

## 3. 信息架构

### 3.1 底部导航

当前原型使用 iOS Tab Bar 视觉。Tab Bar 固定在底部，使用接近 SF Symbols 的线性图标，选中态使用品牌主色 Electric Blue `#2563FF`，未选中态使用 iOS secondary label 灰色。业务卡片和资料类型图标优先使用 emoji，Tab 图标使用线性系统动作图标。

当前底部导航实际为 5 个视觉项，其中 `添加` 是中间突出快捷入口，不是普通内容 Tab。点击 `添加` 后出现半透明遮罩，并在 Tab Bar 上方展开两个横向动作按钮：`添加记录`、`添加对象`。

| Tab | 名称 | 主要内容 |
|-----|------|----------|
| 首页 | 首页 | Today 概览、首页搜索、最近记录、近期提醒、常用对象快捷入口 |
| 记录 | 记录 | 全部记录和资料列表、筛选、待整理入口 |
| 添加 | 添加 | 展开添加记录 / 添加对象快捷动作，不承载独立内容列表 |
| 提醒 | 提醒 | 近期、已完成、已过期提醒 |
| 设置 | 设置 | 资料箱、模板、备份、安全、Pro、隐私 |

搜索放在首页顶部，也可从记录页搜索框进入独立搜索页，不单独做底部 Tab。对象不做底部 Tab，避免产品看起来像复杂资料库；对象入口通过首页常用对象、搜索结果、记录详情、添加对象保存后、或资料包导出流程进入。

禁止使用 Android Bottom Navigation、右下角 FAB 或 Material 风格底部导航。当前中间 `添加` 是 Tab Bar 内的突出按钮，不是右下角悬浮按钮。

### 3.2 关键对象关系

- 空间：家庭空间、经营空间、事业管理空间、自定义空间。
- 记录 / 资料：文字备忘、合同、发票、收据、保修卡、体检报告、检查单、处方、疫苗记录、医保报销资料、照片、PDF、付款截图等。
- 附件：图片、PDF 或其他文件。
- 对象：物品、房屋、家庭成员、健康档案、客户、项目、店铺、公司、证书、求职机会等。
- 事件：购买、签约、付款、维修、就诊、体检、接种、交付、续约、面试、绩效评估等。
- 提醒：保修到期、合同到期、租期到期、复诊提醒、用药提醒、疫苗接种提醒、体检提醒、证照到期、尾款提醒、面试时间等。

## 4. 页面规格

### 4.1 空间选择页

用途：用户进入 App 后选择或创建空间。

页面结构：

- 顶部大标题：凭保
- 副标题：重要资料先存起来
- 空间卡片列表：
  - 🏠 家庭资料箱：房屋、物品、保修、合同、健康和老幼照护资料
  - 🧾 经营资料箱：客户、项目、票据和证照
  - 💼 事业资料箱：合同、绩效、证书和求职资料
  - ✨ 自定义资料箱：Pro 标识
- 每张空间卡片展示：emoji 图标、空间名、资料数量、近期提醒数量、最近更新时间
- 底部或顶部按钮：新建空间
- 免费版限制提示：免费版支持 1 个空间，创建更多空间需要 Pro

交互：

- 点击空间进入空间首页。
- 点击新建空间打开选择空间类型的 Modal Sheet。
- 自定义空间入口带 Pro 标识。

iOS 风格要求：

- 使用大标题 `凭保`。
- 空间列表使用 premium iOS 卡片：浅色背景、细边框、轻玻璃感、品牌 tint，不要像传统表格或安卓卡片。
- 新建空间按钮可放右上角 `plus` SF Symbol，或列表底部使用品牌 Electric Blue tinted button。
- 不要使用安卓式大色块启动页或居中 Logo 欢迎页。
- 文案可把“空间”弱化为“资料箱”，例如“家庭资料箱”“经营资料箱”“事业资料箱”。
- 空间和资料类型图标首选 emoji，例如 🏠、🧾、💼、🩺、📄、💊、💉、🧑‍🧒、🔔。

### 4.2 空间首页

用途：当前资料箱的 Today 概览。首页必须非常简洁，让用户一眼知道“最近保存了什么、有哪些快到期、下一步可以做什么”。

页面结构：

- 顶部先显示全宽搜索框，支持在首页内直接搜索记录、对象、提醒和模板
- 搜索框下方显示当前资料箱名称，例如“家庭资料箱”
- 右上角：切换资料箱图标、更多操作图标
- 顶部 Hero 摘要卡：
  - 记录数量，例如“46”
  - 提醒数量，例如“5”
  - 本地安全状态，例如“本地安全”
  - 待整理、本月新增、近期提醒三个 compact pill 入口
- 状态摘要：
  - 待整理
  - 近期提醒
  - 本月新增
- 常用对象横向快捷入口，当前展示 5 个对象，不作为主要导航
- 即将到期提醒列表
- 最近记录列表

设计重点：

- 首页要像 premium iOS utility 的 Today 页面，不要像后台工作台。
- 首页本身不再单独平铺“写记录、拍照、导入文件”三个快捷按钮；快速添加由底部 Tab Bar 中间 `添加` 控件承载。
- 状态摘要适合使用小型 metric pill 或 compact cards，不要铺满大量统计块。
- Hero 摘要卡可以使用 Electric Blue 到 Soft Indigo 的轻渐变，叠加细腻半透明白色元素，但不能做成营销 banner。

iOS 风格要求：

- 使用 `NavigationStack` 大标题，标题为当前空间名。
- 右上角使用 SF Symbols 风格图标按钮，例如切换资料箱、更多操作。
- 更多操作通过 iOS ActionSheet 样式承载 `编辑资料箱`、`删除资料箱`；删除资料箱需要二次确认。
- 交互要轻快：快速操作按钮支持轻微按压反馈，列表进入详情使用自然过渡，状态卡可以有 subtle spring animation。

### 4.3 快速添加记录页

用途：用最少步骤完成 capture。页面核心不是填表，而是先保存。

页面结构：

- 顶部标题：添加记录
- 顶部显示“添加到 当前资料箱”，并支持切换资料箱
- 顶部操作区实际为两个主入口：
  - 添加照片
  - 添加文件
- 附件预览区：
  - 图片缩略图
  - 视频 / 实况照片标识
  - PDF 文件图标
  - 文件名与大小
- 可选字段默认折叠在“更多详情”或“继续整理”区域中：
  - 标题
  - 类型
  - 日期
  - 金额
  - 对方名称
  - 标签
  - 关联对象
  - 提醒
- 备注正文位于展开后的详细信息区域中，支持普通文本和换行，不需要富文本工具栏
- 顶部右侧按钮为“保存”

关键文案：

- “添加详细信息”
- “可选”
- “选择已保存的对象”
- “设置提醒日期”

交互：

- 用户拍照或导入文件后，即使不填任何字段也可以点击顶部“保存”。
- 默认不要展示完整表单压迫用户；只有点击“继续整理”或展开“更多详情”后才显示类型、日期、金额、关联对象和提醒。
- 当前原型展示相机权限拒绝 sheet、保存成功 toast、关联对象选择 sheet、提醒配置 sheet、资料箱选择 sheet。
- 当前原型没有单独展示“每个文件生成一条记录 / 合并为一条记录”的导入方式分段。

iOS 风格要求：

- 添加记录页在交互模式中作为完整屏幕进入，顶部为 iOS 导航栏样式，包含“取消 / 添加记录 / 保存”。
- 字段区使用 iOS `Form` 分组样式。
- 底部主按钮使用品牌 Electric Blue prominent button，不要用 Material filled button。

### 4.4 记录 / 资料列表页

用途：浏览和筛选记录与资料。

页面结构：

- 搜索框：搜索标题、标签、备注、对象名或文件名
- 筛选入口：位于列表顶部右侧，打开底部筛选 sheet
- 筛选 sheet 当前使用两栏结构：
  - 左侧分类：资料箱、对象、模板、排序
  - 右侧选项列表：多选或单选
- 排序选项：
  - 最近添加
  - 最近更新
  - 日期倒序
  - 即将到期
- 记录卡片：
  - 缩略图或文件图标

## 6. 视觉与组件规范

### 6.1 视觉风格

- 必须贴近 iOS 18 / SwiftUI 原生浅色模式，同时更现代、更 premium、更适合海外 iOS 用户审美。
- 专业、冷静、可信、轻未来感，但不要过于传统、沉闷或企业后台化。
- 品牌主色使用 Electric Blue `#2563FF`，辅助色使用 Mint Teal `#14C8A8`，强调色使用 Soft Indigo `#7C5CFF`。不要回退成纯 iOS system blue 主题。
- 背景使用 Cool Mist `#F6F8FF`，局部分组和列表仍保持 iOS 原生白色 / grouped background 的可读性。
- 主要内容使用 iOS `List` / `Form` / `Section` 组织；首页、状态摘要、空间卡片、Pro 弹窗可以使用更现代的 premium cards。
- 卡片圆角 14-16pt，阴影极轻，优先靠细边框、透明度、渐变 tint 和留白区分信息。
- 不要卡片套卡片。
- 可以有轻微浅色渐变、半透明 tint、轻玻璃感卡片和细腻高光，但不要大面积深色渐变、漂浮装饰球、复杂插画背景或厚重毛玻璃。
- 记录类列表要适合长期扫描和反复使用。
- 字体气质必须接近 SF Pro / San Francisco，不要使用 Roboto、思源黑体网页感标题或花哨字体。
- 页面应有现代海外 App 的精致感：足够留白、清晰层级、轻量动效、少量图标、精准状态色和更强品牌识别度。

- iOS Tab Bar / SwiftUI `TabView` 风格底部导航，包含中间突出 `添加` 快捷入口

- iOS grouped `List` row
- iOS `Form` section
- iOS `Menu`
- iOS Modal Sheet / SwiftUI `.sheet`
- iOS Action Sheet / `confirmationDialog`
- iOS Toggle
- iOS DatePicker
- iOS Stepper 或数字输入
- iOS ProgressView / Storage Bar
- iOS Empty State
- iOS Paywall Sheet
- 轻量 haptic / press feedback 的视觉表达
- 浅色 tint 状态卡
- premium hero summary card
- compact action row
- subtle glass card
- brand gradient accent
- 现代但克制的空状态插图或 SF Symbols 图形

图标策略：

- 系统动作图标使用 SF Symbols：底部 Tab、导航栏按钮、搜索、分享、删除、设置、更多操作。
- emoji 图标要克制使用，尺寸统一，放在浅色圆角底或列表行左侧，避免花哨和幼稚。

emoji 业务图标示例：

## 9. 生成结果验收标准

生成结果应满足：

- 看起来像一个真实 iOS 工具 App，而不是概念页。
- 看起来像 SwiftUI 原生 App，而不是 Android / Material Design App。
- 看起来只服务 iOS 手机端，不像 Web App、小程序或桌面后台。
- 底部导航实际为：首页、记录、中间添加、提醒、设置。中间 `添加` 是快捷操作入口，不是对象或资料列表页；不要把对象做成一级 Tab。
- App 内业务图标优先使用 emoji，系统动作图标使用 SF Symbols，整体不幼稚、不花哨。
- 视觉有 premium、现代、酷感和清晰品牌识别，主体仍保持浅色、干净、不压抑。
- 必须使用定制品牌色：Electric Blue `#2563FF`、Mint Teal `#14C8A8`、Soft Indigo `#7C5CFF`，不能退回普通 iOS 蓝灰系统风格。
- 交互明显更简洁：快速添加由底部中间 `添加` 入口触发，展开 `添加记录` 和 `添加对象` 两个动作；添加记录页只保留 `添加照片`、`添加文件` 两个主入口，整理字段默认后置。
- 第一屏能看出这是重要资料富媒体备忘录。
- 用户能看懂如何添加记录、查找资料、设置提醒和导出资料包。
- 文案口语化，概念简单，用户不需要理解复杂产品术语也能操作。
